# PaperNotes 三语接入指令

请在现有源码根目录 `windows-macos-stickies-1-2-windows` 接入日语、简体中文、英语 UI。附件中的译文已经按 UI 场景整理，不要机器重译，也不要只翻设置页。

## 输入文件

- `ui-text-translated.json`：139 条原始文案的对应译文、唯一资源 Key、原 Key、源码定位和新增文案。
- `ui-text-translated.md`：供人工审阅的三语对照。
- `translations.tsv`：139 条原始条目的日英翻译底稿，仅供对照。

JSON 是翻译映射清单，不是可直接在 WPF 中运行的资源。请按现有项目结构生成真正的资源。原清单中的 Key 有重复，必须使用新 `key`，不要用旧 `source_key` 当字典主键。源码位置可能因修复而变化，请按语义和实际调用定位，不按旧行号盲改。

## 1. 语言选择行为

- 设置的“通用”区添加“言語 / 语言 / Language”下拉框，选项固定显示各语言自己的名字：`日本語`、`简体中文`、`English`。
- 使用稳定代码 `ja-JP`、`zh-CN`、`en-US` 保存，禁止保存列表索引或翻译后的名称。
- 首次启动，以及旧配置没有语言字段时，默认 `ja-JP`，不跟随 Windows 系统语言。旧用户的其他设置和内容保持原样。
- 已选择过语言的用户，下次启动恢复保存的选择；不是每次启动强制日语。未知或损坏的语言值安全回退日语，保留其他可读设置。
- 下拉框只改变待保存值。点现有“保存”成功后应用语言；点“取消”、Esc 或关闭设置窗口不改变语言。保存失败不假装切换成功。
- 目标是无需重启即可切换。切换后更新现有窗口、托盘、菜单、Tooltip、状态、对话框和运行时生成的文案。已经打开的临时菜单或弹层可以安全关闭，下一次打开使用新语言。
- 不通过关闭重开所有便签或重载文档来换语言，不丢失编辑、选区、撤销栈、焦点、窗口位置及保存状态。不要重现之前格式 Popup 重建导致命令二次触发的问题。
- 订阅语言变化事件时，窗口关闭必须释放订阅，避免内存泄漏、重复刷新和重复快捷键注册。

## 2. 资源与术语

- 日英 UI 品牌统一 `PaperNotes`，中文保留“纸间”。这只是显示名，不修改 exe、程序集、命名空间、AppData 路径、互斥体、启动项技术标识。
- 日语：便签=付箋；便签索引=付箋一覧；任务清单=チェックリスト；置顶=常に手前に表示；列表固定=一覧の先頭にピン留め。这两个“置顶/固定”必须区分。
- 英文采用 sentence case，如 `New note`、`Save`、`Always on top`，不要改为每词首字母大写。
- 优先复用项目已有资源方式；没有时用小而明确的 WPF 资源/本地化服务，避免引入大框架和新第三方依赖。
- 所有面向用户的固定文案走资源，不允许“根据当前显示的中文字符串判断业务行为”。颜色与下拉框选项须使用稳定 ID/颜色值，不能因翻译导致选错、丢失旧颜色配置。
- `{notes.Length}`、`{category.Name}` 等是原源码插值说明，不是供运行时求值的表达式。请转换成受控参数（如 `{0}`、命名参数）并建立明确映射，禁止运行时解释执行这些表达式。
- 校验三语占位符集合一致、参数不缺失。路径、异常详情、快捷键名作为参数/独立内容追加，保持可读间距和换行，不把动态值误当格式字符串。
- 对 `Notes.Count`、`Notes.SearchCount`、`Import.PartialResultPrefix` 使用 JSON 中的 `english_singular_overrides`，使 1 note / 1 note found / Imported 1 note 正确。导出说明也处理总数为 1 的语法。不要引入超出需要的复数框架。
- JSON 和资源中使用实际换行；不要把 `&#x0a;` 或字面 `\\n` 显示出来。TXT 文件筛选器只翻译描述，保留 `|*.txt` 和扩展名。
- 某个资源缺失时回退日语，测试必须将缺失项报错，不能只靠回退掩盖漏翻。不要显示资源 Key、空字符串或崩溃。
- 原生 Windows 文件对话框/MessageBox 的系统按钮可能使用 Windows 语言；本轮不强制重写整套原生对话框。自有标题、说明和筛选器必须本地化；系统异常原文保持原样，注明这是系统边界。

## 3. 保护用户内容和现有数据

- 不翻译或批量改写用户的便签正文、标题、分类名、搜索词、文件名和磁盘路径。
- `空白便签`、`未命名便签` 若只是 UI 回退标签，动态本地化；若已写成用户内容，不因换语言批量覆盖。
- `全部`、`未分类` 是系统页签显示名。先检查当前内部查询/Settings/保留名校验是否直接依赖中文。保留稳定内部 ID/现有存储语义，仅翻译显示。切换后保持原分类选择、筛选和搜索，不把用户分类重命名为英文或日文。
- 保留已有保留名规则，不因当前语言改变哪些旧分类能读取。新增语言的保留显示名与用户分类重名时，先核实当前机制，再作最小且不破坏旧数据的处理；不能删除/改名用户分类，也不能把用户分类误当系统页签。
- 颜色保持原来的颜色值；分类仍按原 ID 关联。不要更改 JSON 的现有业务字段名、RichTextRtfBase64、便签内容格式或数据目录。
- 旧设置反序列化向后兼容，保存语言不能重置快捷键、启动项、默认颜色或窗口设置。

## 4. 翻译前后需要核实的语义

译文不是行为证据，请对 JSON 的 `implementation_review` 逐项核实源码后再接入：
- `撤回` 暂按 Undo 译为「元に戻す」，确认实际动作。
- `未分类` 空状态：分类内新建会直接归入分类，因此译文改为“未指定分类的新便签出现在这里”，确认真实行为。
- “清洗后保留完整正文”等恢复提示必须符合真实代码，不因这次翻译改变粘贴或恢复策略，不无依据承诺数据完整。
- 原始清单 139 条只是当前快照。扫描本轮快捷键修复/粘贴修复新增的“设置/修改/录入/取消/纯文本粘贴”等提示，补齐资源；新增翻译可先用附件建议，额外出现的文案在交付中列出。

## 5. 布局与可访问性

- 英文较长，允许说明文本自动换行，优先内容自适应；不要为维持原尺寸裁字或统一缩小字号。
- 日本語、简体中文、English 三个选项不能缺字。以可用字体与合理字体回退支持三语；不通过修改用户便签内的字体实现界面本地化。
- 检查按钮、菜单、分类对话框、设置窗口、错误提示、空状态、托盘菜单在三语下不遮挡。
- 保留 Tab 顺序、焦点提示、快捷键录入、Esc 取消；补齐自有控件的可访问名称和 Tooltip。

## 6. 实施与验证

先保护已有修改，记录本轮源码检查点。使用独立测试数据目录及隔离发布，不触碰真实 AppData、不覆盖正在使用的正式版、不改桌面快捷方式。

必要检查：
1. 三套资源唯一 Key、覆盖率、非空、占位符、筛选器和换行校验。
2. 新配置首次启动为日语；旧配置缺语言字段也为日语；未知值回退日语且其他配置不丢。
3. 日→中→英→日切换，保存、取消、保存失败、关闭重开后的语言行为。
4. 设置、全部便签窗口、索引、菜单、托盘、分类、提示和动态文案同步，无残留的旧语言 UI；正常情况下只允许用户内容、品牌与系统返回文本保留原语言。
5. 内容、便签 ID、分类 ID、颜色值、隐藏/置顶/固定、当前搜索与筛选不受切换影响；不关闭便签，不损坏撤销。
6. 数量为 0/1/2 的日英文案正确；含引号、花括号、emoji 的分类名作为参数正常显示。
7. 本轮快捷键录入/清除/冲突、字体单步增减、Unicode 粘贴与保存重开回归通过。不要为过测试改字号、粘贴、IME 或存储逻辑。
8. 三语在 100%/150%/200% 缩放及较长文本下检查布局。无法实际执行的 UI 项目注明“未验证”，不能报告为通过。

测试失败时记录首次失败及原因，修复后再验证，不用反复重跑或延长等待掩盖偶发失败。

交付：修改文件清单、最终覆盖条数、资源检查结果、行为与回归结果、未验证事项，以及新版隔离发布完整路径。能启动界面时启动隔离版让我验收；不能时给可复制的准确启动命令。完成后按实际行为小范围更新 README/使用说明，不把翻译文件本身当作已经完成三语功能。
